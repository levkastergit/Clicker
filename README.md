# Автокликер

Автокликер для Windows: клики мыши, нажатия клавиш, ввод текста и последовательности
действий в выбранное окно. Глобальные горячие клавиши, съём координат под курсором,
запись действий, значок в трее, обновление из GitHub.

## Возможности

**Действия**
- Клик левой, правой или средней кнопкой: одинарный, двойной, тройной.
- Клик в точку окна или там, где сейчас курсор. Случайный разброс позиции.
- Нажатие клавиши: группы (специальные, F1–F12, цифры, латиница, кириллица ЙЦУКЕН)
  или любая клавиша через «Нажать клавишу…».
- Два способа отправки клавиши: **нажатие** (код клавиши, символ зависит от
  раскладки окна — для игр) и **символ** (сам символ независимо от раскладки — для полей ввода).
- Ввод текста посимвольно.
- **Зажим**: кнопка мыши или клавиша удерживается заданное время (0 = пока не
  остановят). Клавиша держится с автоповтором, как на клавиатуре; при зажатой кнопке
  мыши окно получает движения мыши с флагом кнопки. При остановке всё отпускается.
- Случайный интервал между действиями, лимит повторов.

**Последовательности**
- Список шагов: клик, клавиша, текст, пауза; у каждого своя пауза после.
- Добавление, редактирование, перестановка, экспорт и импорт в JSON.
- **Запись**: нажмите горячую клавишу и выполняйте клики и нажатия в целевом окне —
  шаги появляются в списке сразу, с реальными задержками; нажмите ещё раз, чтобы закончить.
  Удержание клавиши или кнопки дольше 0,35 с записывается как зажим на измеренное время,
  автоповтор зажатой клавиши не плодит шаги. Клик засчитывается, если окно под курсором —
  цель, принадлежит тому же процессу или точка внутри окна цели; остальные клики
  считаются «вне окна» и показываются в статусе.
  Мышь записывается опросом состояния кнопок (а не хуком), поэтому клики от драйверов
  и утилит мыши, помеченные как программные, тоже записываются. В статусе во время
  записи видны счётчики сырых событий мыши и клавиатуры — по ним понятно, доходят ли
  нажатия до программы.

**Профили окон, именованные действия и последовательности**
- У каждого окна свой набор действий и последовательностей: выпадающие списки
  «Действие» и «Последовательность» показывают только элементы этого окна.
  Кнопки «Новое», «Переименовать», «Удалить», «Из других окон…» (привязать общий
  элемент или сделать копию).
- Окно узнаётся **не по HWND**, а по имени процесса, классу окна и заголовку.
  После перезапуска программы-цели её окно находится заново (точный заголовок →
  частичное совпадение → процесс и класс), и все действия подхватываются автоматически.
  Если целевое окно закрыли, программа ждёт его появления и сама переключается
  на новое окно.
- Всё сохраняется автоматически в `%APPDATA%\Autoclicker\settings.json`.

**Способы ввода** (вкладка «Настройки»)
- **Фоновый** — `PostMessage` в окно: окно может быть неактивным, курсор не двигается.
  Клавиши адресуются окну с фокусом внутри целевого, клики — дочернему окну под точкой.
- **Реальный ввод** — `SendInput`: события проходят через системную очередь ввода,
  как с физической мыши и клавиатуры (скан-коды клавиш, перемещение курсора).
  Окно активируется перед вводом, курсор возвращается на место после остановки.

  Это максимум, доступный без драйвера. Низкоуровневые хуки всё же могут отличить
  такой ввод по флагу `LLKHF_INJECTED`.

**Координаты с привязкой к размеру окна**
- Наведите курсор на нужную точку целевого окна и нажмите горячую клавишу съёма
  координат (по умолчанию F8). Окно под курсором станет целевым.
- Вместе с точкой запоминается размер клиентской области окна. При включённой
  привязке точка пересчитывается пропорционально текущему размеру, поэтому
  изменение размера окна или масштаба не сбивает клик.

**Горячие клавиши** (глобальные, работают при свёрнутом окне)
- Старт/Стоп — F6, съём координат — F8, запись — F9. Все переназначаются.

**Трей**
- Значок показывает состояние: серый — остановлен, зелёный — работает, красный — запись.
- При сворачивании окно уходит в трей. Меню: показать, старт/стоп, выход.

**Свёрнутое целевое окно** (вкладка «Настройки»)
- Заставить чужую программу обрабатывать ввод в свёрнутом окне извне нельзя — это
  решает она сама, игры обычно останавливают обработку. Обход, включённый по умолчанию:
  на время работы окно разворачивается без активации, на миг активируется, чтобы
  программа восстановила фокус, и прячется под другие окна (или выносится за край экрана).
  Для программы оно «не свёрнуто», вам не мешает, после остановки сворачивается обратно.
- Другие варианты: спросить перед запуском или не трогать окно.
- **Игры на Unity и Unreal Engine** (Core Keeper, Valheim, Rust и др.) читают ввод напрямую
  с устройств через Raw Input, а не из оконных сообщений. Для них работает только
  «Реальный ввод», а он всегда идёт в активное окно: свёрнутая игра ввод не получит,
  и это не обойти без драйвера. Программа подсказывает это рядом с профилем окна, а при
  включённой настройке «возвращать окно на передний план» сама восстанавливает и
  активирует игру, если её свернули или перекрыли во время работы. Пока окно не активно,
  ввод не отправляется, чтобы не попасть в другую программу.

**Прочее**
- Остановка, если окно закрылось или перестало принимать ввод.
- Тёмная, светлая и системная темы. Настройки сохраняются между запусками
  в `%APPDATA%\Autoclicker\settings.json`.
- Кнопка обновления из GitHub.

## Требования

- Windows 10/11
- Python 3.10+ и пакеты из `requirements.txt` (customtkinter, pystray, Pillow)
  — либо готовый `Autoclicker.exe` из [релизов](https://github.com/levkastergit/Clicker/releases).

## Запуск

```
pip install -r requirements.txt
python clicker.py
```

Или двойной клик по `Автокликер.vbs` — запуск без окна консоли.

## Обновление

Кнопка **«Обновить программу»** во вкладке «Настройки»:

| Как запущена программа            | Что делает кнопка                                   |
|-----------------------------------|-----------------------------------------------------|
| Скрипт в клоне репозитория + git  | `git fetch` и `git pull --ff-only origin main`      |
| Скрипт без git                    | скачивает zip ветки `main` и заменяет файлы         |
| Собранный `.exe`                  | скачивает `.exe` из последнего релиза GitHub Releases |

**Известная проблема при обновлении с версий 2.0.0 и 2.1.0.** После установки
обновления может появиться окно «Failed to load Python DLL … _MEI…\python312.dll».
Новая версия при этом уже установлена — просто запустите программу ещё раз.
Причина: загрузчик PyInstaller передаёт дочерним процессам переменные `_PYI_*`,
и новый exe, запущенный скриптом обновления старой версии, искал библиотеки
во временной папке старой версии. Начиная с 2.1.1 скрипт обновления очищает
эти переменные, и дальнейшие обновления проходят без ошибки.

## Сборка exe

```
pip install pyinstaller
pyinstaller Автокликер.spec
```

Готовый файл появится в `dist/Автокликер.exe`. Чтобы кнопка обновления работала
в exe-версии, выложите файл в GitHub Releases с тегом, совпадающим с `__version__`
в `clicker.py` (например `v2.0.0`). Имя файла в релизе должно быть латиницей,
например `Autoclicker.exe`: кириллические имена GitHub заменяет на `default.exe`.

## Структура

- `clicker.py` — интерфейс (CustomTkinter)
- `actions.py` — модель шагов, позиция с привязкой к размеру окна, поток выполнения
- `library.py` — именованные действия и последовательности, профили окон, идентификация окна
- `input_backend.py` — отправка ввода: PostMessage и SendInput
- `winapi.py` — обёртки user32, таблицы клавиш, горячие клавиши
- `hotkeys.py` — глобальные горячие клавиши (RegisterHotKey)
- `recorder.py` — запись действий (низкоуровневые хуки)
- `tray.py` — значок в трее (pystray)
- `settings.py` — сохранение настроек
- `updater.py` — проверка и установка обновлений
- `assets/` — иконка
- `Автокликер.spec` — конфигурация PyInstaller
